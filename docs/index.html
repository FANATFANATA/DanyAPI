Features

Everything the paid APIs have.
None of the bills.

A drop-in replacement for the official OpenAI API - your existing client code just works.

OpenAI-compatible

GET /v1/models and POST /v1/chat/completions with the official request format. Swap base_url, keep your client.

SSE streaming

Real-time streaming via data: chunks and data: [DONE], with live thinking traces as reasoning_content.

Thinking traces

DeepSeek and Qwen reasoning exposed to your app - streamed live, both providers, exactly like the official API.

Tool calling

Emulated tools, tool_choice and parallel_tool_calls with proper finish_reason: "tool_calls" responses.

JSON mode

response_format with json_object and json_schema - structured output for your agents.

Server-side sessions

Multi-turn chats live on the server. Stateless clients keep context automatically via message fingerprinting.

Web search

Turn on grounded, up-to-date answers with the search flag on DeepSeek models.

File attachments

Images and text files as base64 or data URIs. Vision, OCR and file analysis per model - up to 50 files, 100 MB each.

Real token usage

OpenAI-style usage accumulated per conversation, including streaming via stream_options.include_usage.

Survives restarts

Sessions, affinities and usage counters are persisted to disk. Conversations survive server restarts.

Account pool

N tokens = N parallel generations. Requests are distributed round-robin, retried with exponential backoff.

Health ready

GET /health reports provider status and cache stats - perfect for readiness probes and load balancers.

Quick start

Up and running in
under a minute.

One-command install on Windows, Linux and macOS. No Python setup gymnastics required.

PowerShell 
irm https://raw.githubusercontent.com/FANATFANATA/DanyAPI/main/docs/install.ps1 | iex
Linux / macOS 
curl -fsSL https://raw.githubusercontent.com/FANATFANATA/DanyAPI/main/docs/install.sh | bash

The script clones the repo, installs dependencies, creates .env, live-checks your provider tokens and launches the server. It even auto-updates itself on each start.

Python 
# works with any OpenAI-compatible client
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="dummy")
r = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(r.choices[0].message.content)

api_key is required by the SDK but never checked - all requests are made by the server-side accounts.

curl 
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-v4-flash", "messages": [{"role": "user", "content": "Hello!"}]}'
curl + thinking + stream 
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-v4-pro", "messages": [{"role": "user", "content": "2+2?"}], "thinking": true, "stream": true}'

Thinking traces stream live as reasoning_content. Add "stream_options": {"include_usage": true} for usage in the final chunk.

Docker · GHCR 
docker run -d -p 8000:8000 \
  -e DEEPSEEK_TOKENS="token1,token2" \
  -e QWEN_TOKENS="token3" \
  ghcr.io/fanatfanata/danyapi:latest

Prebuilt image, pushed on every commit and every version tag. The native PoW solver is compiled into the image for maximum speed.

Runs on free provider tokens

You add your free DeepSeek/Qwen tokens to .env and all upstream requests are made by those server-side accounts. Your API consumers just point their client at your instance - no keys on their side.

Parallel by design

One account = one message at a time. DanyAPI keeps a pool of tokens and distributes concurrent requests across accounts, queuing when all are busy.

Sessions that survive

Chats live server-side like the web clients. session_id pins a conversation; stateless clients are matched by message fingerprint automatically.

Emulated, normalized

Tool calling and JSON mode are emulated at the proxy layer with prompt injection, then normalized to perfect OpenAI-shaped responses.

FAQ

Questions?
Answered.

Is it really free?

Yes. DanyAPI talks to the internal APIs of the free web clients chat.deepseek.com and chat.qwen.ai using server-side accounts created from your own free provider tokens. There is no billing and no quotas.

Do my users need an API key?

No. The OpenAI SDK requires the api_key field, but DanyAPI never checks it - pass any dummy value. All upstream requests are made by the server accounts you configure.

Which providers and models?

DeepSeek (deepseek-v4-flash, deepseek-v4-pro, deepseek-v4-vision) and Qwen (qwen3.8-max, qwen3.7-plus, … - fetched live from the account). Route by model name; both can run at once.

Can I use it with agents and tool calling?

Yes - emulated tools, tool_choice and parallel_tool_calls with finish_reason: "tool_calls". Clients that ship many tools (like opencode) work out of the box.

What are the account limits?

One account generates one message at a time, so a pool of N tokens gives N parallel generations. DeepSeek and Qwen pools are independent. Busy errors are retried automatically up to 5 times with backoff.

Do conversations survive restarts?

Yes. Session ids, context fingerprints, account affinity and token usage are persisted to disk (JSON files) with atomic writes. In Docker, mount DANYAPI_CACHE_DIR as a volume.
